# Agent Instructions

`scopemux-core` is the native ScopeMux engine: Tree-sitter parsing, AST/CST extraction, project IR, and context products.

## Most Important Notes

- Do not write "you" or "your" in code comments. Use a standard documentation tone, and note useful information, caveats, and todo/action items. Update existing comments that do not follow this practice, and clarify vague messages.
- Build the Python bindings with `./scripts/build_all_and_pybind.sh` from the project root only when Python is involved in the task. Otherwise run the language script relevant to the task.
- Do not run test suites by manually executing raw command strings. Run tests through the shell scripts in the project root. Only target a single test directly when necessary, and that is not preferred.
- Example files and their JSON validation cases exist under `core/tests/examples/<lang>/`. Some are gitignored but present on disk; treat those paths as valid.
- Test example copies are placed under `build/core/tests/examples/*`.
- For the easiest debugging, run the relevant test shell script once and inspect the `.txt` output file of the same name.

## C Best Practices

- Never forward-declare a typedef for an enum in a header unless the full definition is also provided in the same place.
- Always include the header that defines a typedef before using the typedef name in function signatures or struct fields.

## Tree-sitter Parsing

Tree-sitter provides incremental, multi-language parsing. It outputs concrete syntax trees (CSTs) directly from source and supports semantic extraction through Tree-sitter queries. The engine supports dual-mode parsing.

### CST (Concrete Syntax Tree)

- Source: direct output of Tree-sitter.
- Structure: includes every token, punctuation, and structure.
- Generation: recursively traverses the Tree-sitter node tree (see `ts_tree_to_cst`).
- Uses: precise source range and token alignment, code formatting and low-level transformation, reconstruction of original source.

### AST (Abstract Syntax Tree, Query-Driven)

- Source: built by executing `.scm` Tree-sitter queries to extract semantic constructs.
- Managed by `QueryManager` (caching and loading).
- Generated by `ts_tree_to_ast`.
- AST nodes represent functions, classes, methods, control structures, and variable declarations, and are extensible via custom `.scm` queries.
- Uses: high-level code understanding, InfoBlocks, Symbol IR, Call-Graph IR, refactoring, and semantic tools.

## Integration Components

- `tree_sitter_integration.c`: wraps the Tree-sitter C API and provides CST/AST extraction.
- `parser.c`: coordinates the parsing process; manages `ParserContext`, memory, and orchestration.
- `query_manager.c`: loads, compiles, and caches `.scm` query files.
- `parser.h`: declares `ASTNode`, `CSTNode`, and lifecycle methods (`_new`, `_free`, `_add_child`).

## How To Extend

Add new semantic constructs:

1. Create a query file, for example `queries/python/classes.scm`.
2. Update `ts_tree_to_ast` to handle the new capture patterns.

Add a new language:

1. Integrate the Tree-sitter grammar.
2. Add the appropriate `.scm` queries.
3. Register the language in `QueryManager` and the parser initialization logic.

## CST vs AST

| Feature | CST | AST |
| --- | --- | --- |
| Scope | Full syntax (lossless) | Semantic constructs only |
| Language | Language-specific | Language-agnostic |
| Use cases | Formatting, reconstruction, low-level tools | Refactoring, analysis, IR generation |
| Structure | Every token preserved | High-level constructs only |
